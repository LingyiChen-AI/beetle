# 建 issue

报告 markdown 和「飞书文档记录」共用同一份（在当前目录的 `reports/` 下，第一行 `## <bug 标题>` 作为 issue 标题，其余为正文），结构：

```
## <bug 标题，一句话>

**复现步骤**

1. ...

**修复建议**

1. ...（文件路径:行号）

**数据依据**：<关键查询结果的一句话摘要>

**提出人**：<姓名>

**提出时间**：<YYYY-MM-DD HH:MM>

**代码版本**：<分支> @ <提交号>
```

然后执行：

```
{{PYTHON}} {{SKILL_DIR}}/scripts/create_issue.py --project <项目名> --file reports/<文件名>.md
```

- 平台按项目仓库地址自动选（gitee.com → Gitee，github.com → GitHub），仓库、token 环境变量名都取运行时配置（环境变量 `BEETLE_RUNTIME`，客户端自动注入），不要自己传。
- 只想看本项目的记录方式、token 有没有配置：加 `--plan`（不联网、不建 issue）。
- 输出「已创建 issue：<链接>」或「已在 <链接> 追加评论」才算成功，把链接写进最终报告【记录】。
- 退出码 3（未配置 token）或其它失败：**不要换参数重试**，也不要自己找 token；不影响写飞书文档，在【记录】里如实写「issue 未创建：<原因>」。
- token 只在脚本内部使用，不要读取、打印、写进报告或文档。正文里不出现口令、token、手机号、买家昵称或收货信息。

## 建飞书项目工单

本项目记录方式勾了「建飞书项目工单」（运行时配置 `projects.<项目名>.record.meegle` 为 true）时，用同一份报告执行：

```
{{PYTHON}} {{SKILL_DIR}}/scripts/create_work_item.py --project <项目名> --file reports/<文件名>.md
```

- **优先级**按项目清单里的「优先级规则」判断（P0～P3 各对应什么情况），用 `--field 优先级=Px` 传。
- **处理人**：项目清单里有「分派规则」时，按规则从「候选处理人」里选一个，用 `--assignee 姓名` 传（姓名照抄候选名单）；
  写的是「都派给默认处理人」或判断不出来就不传。输出里有「[注意] … 已改派给默认处理人」时照实写进【记录】。
- **需要判断的字段**（运行时配置 `meegle.ai_fields`，项目清单里「建单时按问题判断：」后面列了字段和可选项，如优先级、涉及端、业务线）：
  按这次问题的影响面、出问题的端、所属业务自己判断，每个字段加一个 `--field 字段名=选项名`（选项名照抄可选项），例如
  `--field 优先级=P1 --field 涉及端=服务端 --field 业务线=质检`。拿不准时选最接近的，不要漏传；用 `--plan` 可以看到要传哪些。
- 空间、工单类型、固定字段（必填下拉）、默认处理人都取运行时配置里项目的 `meegle` 段，不要自己传；名称取报告标题，描述取正文，「报告人」这类人员字段自动填当前登录用户。
- 只想看配置：加 `--plan`（不建单）。
- 输出「已创建飞书项目工单：<链接>」或「已在飞书项目工单 <链接> 追加评论」才算成功，把链接写进最终报告【记录】。
- 退出码 3（没装 / 没登录飞书项目 CLI）、2（配置缺必填字段）或其它失败：**不要换参数重试**，也不要自己调 meegle 建单；不影响建 issue 和写飞书文档，在【记录】里如实写「飞书项目工单未创建：<原因>」。

## 建飞书任务

本项目记录方式勾了「建飞书任务」（`projects.<项目名>.record.feishu_task` 为 true），并且按记录规则这次该建任务时，用同一份报告执行：

```
{{PYTHON}} {{SKILL_DIR}}/scripts/create_task.py --project <项目名> --file reports/<文件名>.md
```

- 以机器人主人的身份建；清单、负责人、截止天数取运行时配置里项目的 `feishu_task` 段，不要自己传。同一天同项目同标题不会重复建。
- 输出「已创建飞书任务：<链接>」才算成功；失败**不要换参数重试**，在【记录】里如实写「飞书任务未创建：<原因>」。
